# Hardware Trust Model

## Core Axiom

> Measurements MUST occur below attacker-controlled code.

A software process that measures itself provides no security guarantee.
A compromised process can pass any bytes it chooses to a hash function and
produce a cryptographically valid measurement of code that is not running.

## Trust Hierarchy

```
Physical Hardware (CPU, TPM chip, HSM)
  └── Hardware Root of Trust (TPM firmware / DICE UDS / CPU microcode)
        └── Measured Boot Chain
              ├── PCR[0]: Firmware (UEFI/ROM) — measured by TPM before OS loads
              ├── PCR[1]: Bootloader — measured by firmware
              ├── PCR[2]: Kernel — measured by bootloader
              ├── PCR[3]: Initrd — measured by bootloader
              ├── PCR[4]: Config — measured by bootloader
              └── PCR[5..7]: Application-defined
                    └── AttestationQuote (ML-DSA-65 signed)
                          └── Verifier (PKI + policy + Bitcoin anchor)
```

## Backend Security Boundaries

| Backend | Measurement Root | Attacker Boundary | Production? |
|---------|-----------------|-------------------|-------------|
| TPM 2.0 | TPM firmware (separate chip) | Below OS kernel | ✅ Yes |
| DICE | Hardware UDS (eFuse/OTP) | Below bootloader | ✅ Yes |
| Intel TDX | CPU microcode | Below VMM | ✅ Yes (Phase 4) |
| AMD SEV-SNP | AMD PSP firmware | Below hypervisor | ✅ Yes (Phase 4) |
| Nitro Enclave | Nitro hypervisor | Below guest OS | ✅ Yes (Phase 4) |
| SoftwareRoT | None | None | ❌ Test only |

## Security Assumptions

1. The TPM chip is genuine hardware (validated via EK certificate chain).
2. The TPM firmware has not been compromised (manufacturer trust anchor).
3. The measured boot chain was not interrupted (PCR extend chain is intact).
4. The device signing key is stored in TPM NV or equivalent protected storage.
5. The nonce was generated by the verifier and not reused.
6. The certificate chain terminates at an offline root CA.

## What Hardware Attestation Does NOT Prove

- That the running software is free of vulnerabilities.
- That the device has not been physically tampered with after manufacturing.
- That the TPM manufacturer is trustworthy (requires separate EK cert validation).
- That the firmware is free of supply-chain compromise (requires Sigstore provenance).

## Threat Model Updates (Phase 2.5)

| Threat | Mitigation |
|--------|-----------|
| Compromised firmware self-attests | TPM measures firmware before it runs |
| Slot reassignment attack | `PcrMeasurement::new()` enforces canonical slot mapping |
| SHA-256/SHA3-256 confusion | `TypedDigest` carries algorithm explicitly |
| Weak software counter | `CounterEvidence::HardwareMonotonic` required by production policy |
| TestOnly backend in production | `unsafe-test-backend` feature required; policy rejects it |
| TPM clock reset attack | `TpmClockInfo::safe` flag checked; `RequireMinCounterValue` rule |
| Nonce replay | `TpmQuoteVerifier` checks `qualifying_data` first |
